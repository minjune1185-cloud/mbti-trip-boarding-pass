# 「성격따라 따라가는 여행」 PRD (1차 MVP)

## 1. 개요

* **서비스명**: 「성격따라 따라가는 여행」 (1차 MVP)
* **목표**: 여행 조건 객관식 선택 → AI가 한국인 인기 30개국 중 여행지·이유를 밈 텍스트 보딩패스 카드로 추천 → 이미지 저장 후 직접 공유하는 모바일 전용 무료 웹앱 구현
* **운영 방식**: 1차 `Stateless` (DB 미연동), 무료티어 AI API 기반 운영
* **문서 확인 메모**: 첨부 문서1도 초기 화면설계서(MVP) 파일임. 문서1·문서2에 명시된 핵심 기능 1~3 및 4개 화면(`S1`~`S4`) 기준으로 PRD 통합 작성. 미기재 기획 항목은 추측 없이 '남은 질문'에 분리.

---

## 2. 사용자와 사용 상황

* **사용자**: 모바일 웹에서 무료로 AI 밈 여행지 추천받고, 결과 카드 이미지 저장해 직접 공유하는 사용자 *(세부 타깃·페르소나 미정 → 남은 질문 참고)*
* **사용 상황 (Flow)**:
  1. 모바일 웹 `S1` 진입, 7개 객관식 여행 조건(동행자 '혼자' 선택 시 6개) 선택 후 제출 버튼 클릭
  2. `S1` 로딩 오버레이 대기
  3. 성공 시 `S2` 보딩패스 결과 카드 확인 → 이미지 기기 저장 후 갤러리에서 카톡·인스타 직접 공유, 필요 시 `다시 추천받기`로 `S1` 복귀
  4. IP 요청 제한 초과 시 `S3` 차단 화면 확인 후 `S1` 복귀
  5. 무료티어 할당량 소진 시 `S4` 서비스 일시 중단 안내 확인

## 4. 저장되는 것

* **DB 영구 저장**: 없음. 1차 `Stateless` (DB 미연동), 사용자 입력·결과 미저장
* **클라이언트 런타임 메모리 (임시)**:
  * 사용자 선택 조건 `input_payload` JSON (`다시 추천받기`·새로고침 시 초기화)
  * AI 응답 `Structured Outputs(JSON)` 필드: `country`, `meme_title`, `meme_reason`, `tags` (새로고침 시 소실)
* **서버 런타임 (임시)**:
  * IP별 요청 횟수 카운트 (분당 3회, 일 20회 `Rate Limit` 판별용 — 저장소 미정)
* **사용자 기기 로컬**:
  * `보딩패스 이미지 저장` 클릭 시 캡처된 보딩패스 카드 이미지 파일

## 5. 규칙

* **입력 항목 및 선택지**:
  1. **여행 스타일 (택1)**: 휴양·호캉스 / 맛집·먹방 / 관광·랜드마크 / 쇼핑·도시 / 액티비티·자연
  2. **본인 MBTI**: 16종
  3. **예산 (1인)**: 50만 이하 / 50~100만 / 100~200만 / 200~300만 / 300만 이상
  4. **기간**: 2박 3일 이하 / 3박 4일 / 4박 5일 / 1주일 이상
  5. **치안 중요도 (택1)**: 치안 최우선 / 보통(무난) / 모험 가능
  6. **동행자**: 혼자 / 친구(텐션 높음) / 친구(힐링) / 연인 / 가족
  7. **동행자 MBTI**: 16종 + 모름
* **필수 조건 규칙**: 동행자 '혼자' 선택 시 동행자 MBTI 숨김 및 필수 조건 자동 제외(총 6개 필수). 그 외 선택 시 동행자 MBTI 노출 및 필수 조건 포함(총 7개 필수). 필수 항목 1개라도 미선택 시 제출 버튼 `Disabled`.
* **응답 분기 규칙**:
  * 정상 응답 → `S2` 이동
  * IP `Rate Limit` (분당 3회, 일 20회) 초과 → `S3` 이동
  * 무료티어 할당량 소진 → `S4` 이동
  * 일시적 네트워크/API 오류 → `S1` 유지, 로딩 해제, 하단 오류 토스트 노출
* **보딩패스 카드 구성 규칙**: 한국인 인기 30개국 중 1곳 추천(치안 중요도 기준 반영). 밈 이미지 없음, 텍스트 전용. AI 4개 필드(`country`, `meme_title`, `meme_reason`, `tags`) + 유저 선택 요약(본인 MBTI·예산·기간·동행자·치안 중요도) 표기.
* **고지 및 안내 문구 규칙**:
  * `S1` 하단: *"본 서비스는 무료티어 AI로 운영되며, 일일 무료 할당량이 소진되면 충전 전까지 발권이 중단될 수 있습니다. 입력하신 정보는 별도 저장되지 않습니다."*
  * `S2` 인앱 안내: *"카톡·인스타 앱 내에서 저장이 안 된다면, 외부 브라우저(크롬·사파리)로 열어 저장해 주세요."*
  * `S4` 중단 정책: 무료티어 충전 전까지 제출·재시도 버튼 미제공.

## 6. 안 할 것

* **DB 연동 및 개인정보·연구 데이터 저장**: 1차 `Stateless` 유지. 연구 데이터 동의 체크박스는 2차 DB 연동 시점 추가.
* **밈 이미지 생성/노출**: 보딩패스 카드에 밈 이미지 미포함.
* **외부 공유 API 연동**: 카톡·인스타 등 외부 공유 API 미사용 (이미지 로컬 다운로드 후 직접 공유).
* **별도 로딩 화면**: `S1` 위 로딩 오버레이만 사용.
* **유료 결제 및 과금 기능**: 무료 웹앱, 무료티어 AI API 한정 운영.
* **PC 전용 레이아웃**: 모바일 웹 뷰포트 전용.
* **`S4` 내 제출/재시도 액션**: 할당량 소진 중 신규 발권 차단.

## 7. 만드는 방법

* **프론트엔드 (모바일 웹)**:
  * 4개 화면(`S1`~`S4`) 라우팅·상태 관리 구성. `S2` 빈 상태 직접 접근·새로고침 감지 시 `S1` 자동 리다이렉트 처리.
  * `S1`: 7개 객관식 폼 상태(치안 중요도 포함)·동행자 '혼자' 조건부 검증·`input_payload` JSON 생성·중복 클릭 방지·로딩 오버레이 구현.
  * `S2`: 세로형 보딩패스 카드 DOM 구현, `html-to-image` (또는 `html2canvas`)로 카드 영역 캡처 후 이미지 다운로드·완료 토스트 트리거.
* **백엔드 / API**:
  * `input_payload` JSON 수신 API 구현 (`travel_style`, `my_mbti`, `budget`, `duration`, `safety_level`, `companion`, `companion_mbti`).
  * IP 기반 `Rate Limit` (분당 3회, 일 20회) 검사 로직 적용 → 초과 시 `S3` 분기용 응답 반환.
  * 무료티어 AI API 호출 시 `Structured Outputs(JSON)` 강제 (`country`, `meme_title`, `meme_reason`, `tags`) 및 치안 중요도(`safety_level`) 필터링 규칙 반영.
  * 무료티어 쿼터 소진 상태 감지 또는 API 할당량 초과 에러 수신 시 `S4` 분기용 응답 반환.

## 8. 남은 질문

1. **문서1 확인**: 첨부 문서1이 원본 기획서가 아닌 초기 화면설계서(MVP)임. 원본 기획서에 추가된 타깃 사용자·비즈니스 목표·2차 연동용 스텁(stub) 요구사항 있는지?
2. **한국인 인기 30개국 목록**: 추천 후보 30개국 확정 리스트 및 표기 형식(한글명/영문명/공항코드 여부)은?
3. **기술 스택 및 배포 환경**: 프론트엔드·백엔드 프레임워크(Next.js App Router), 호스팅 플랫폼(Vercel) 확정.
4. **AI API 모델 및 출력 제약**: 사용할 무료티어 AI API·모델명(`gemini-3.5-flash-lite`), 밈 톤앤매너·금칙어 기준, `meme_title`(25자 이내)·`meme_reason`(90~140자) 최대 글자 수, `tags` 개수(3~4개)·자료형(배열) 확정 반영.
5. **`input_payload` JSON 스키마**: 7개 항목 정확한 Key 이름(`travel_style`, `my_mbti`, `budget`, `duration`, `safety_level`, `companion`, `companion_mbti`)과 동행자 '혼자' 선택 시 동행자 MBTI 처리 방식(`null`) 확정 반영.
6. **보딩패스 탑승 조건 요약 범위**: `S2` 카드 요약에 `본인 MBTI·예산·기간·동행자·치안 중요도` 표기 반영.
